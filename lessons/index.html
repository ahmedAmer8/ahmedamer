Each entry is one thing I got wrong in production and what proving it taught me. Filter by state or kind. Unresolved entries are marked; they stay here until I can close them honestly.

16 entries
001

Two machines were running the same scheduler, and customers got everything twice

The scheduling tool writes per-host entries, so every instance that boots installs its own copy. Two boxes meant two of every sweep — including the ones that message customers.

A scheduler that installs itself at boot has no concept of a fleet. Exactly-one has to be enforced by a lease, not by the number of machines you believe you have.

002

The schedule fired twice an hour, not every fifty-five minutes

`*/55 * * * *` does not mean "every 55 minutes." It means minute 0 and minute 55. The job it scheduled rewrote a 30,000-token cache each time, for months.

A step value in a cron field steps within that field's range and resets at its boundary. Any interval that does not divide its unit evenly does not mean what it reads like.

003

We told the agent to sell something that did not exist

A cluster of conversations where the agent invented offers had a single, entirely non-AI cause: a configuration field instructing it to reference a promotion that only existed on a different tenant's menu.

When a model hallucinates consistently in one domain, audit what its configuration promises against what its data contains. Instructing a model to cite a nonexistent thing while forbidding invention leaves it one option.

004

I wrote a careful latency analysis, then measured it and two conclusions flipped

Six prioritised recommendations, reconstructed from log timestamps. When the tracing arrived, one was inverted, one was overstated by 3x, and the largest problem in the system was not in the document at all.

An estimate reconstructed from adjacent data is a hypothesis. Label it as one, and keep it visible after the measurement so the correction is legible.

005

The security signal went to zero and both explanations are bad

A steady 3.4% prompt-injection deflection rate fell to zero over two days. No deploy, no model change, no errors. Either detection went dark, or we had been turning away real customers for weeks. I still do not know which.

A monitored rate falling to zero is an event. Design the alert for "this signal stopped" as carefully as the one for "this signal spiked."

006

The security guard was turning away customers, nondeterministically

A printed QR code produced a prefilled message that asserted a role. The prompt-injection classifier read it as an attack and deflected 132 of 730 arrivals in a month — on byte-identical input, inconsistently.

Before a classifier can block anything, enumerate the legitimate inputs that structurally resemble an attack. Your own system generates some of them.

007

The cost dashboard was wrong by 3.8x, confidently

We were reporting $6,712 of model spend against $1,767 of actual spend, because the pricing treated cached input tokens as an addition to input tokens rather than a discounted subset of them.

Derive a billing model from the provider's own usage rows, not from the shape the API response suggests. A plausible reading of a field is not a measurement of it.

008

A menu that cost 19,369 queries

The single largest latency problem in the product was not in the latency document, because nobody had measured it. One translated label, one query — repeated across the whole catalogue, on every turn.

An N+1 is invisible on a development dataset and linear in production data. Profile against a realistic catalogue, not a seeded one.

009

The same change measured as a 6.8-second win and a 1.2-second loss

Benchmarking against a remote model by running one arm then the other lets the provider's own load drift decide the result. Twice it decided wrongly, in opposite directions.

Any A/B against a service you do not control must interleave its arms and report a second quantity that does not depend on the network.

010

The slowest thing in the system was the thing protecting it

The order validator took 10.38 seconds on average — more than twice the agent turn it guards. The cause was not the model. It was reasoning nobody had capped, and measuring it correctly required interleaving the two arms.

When a model call is slow, measure its thinking tokens before you change the model. The budget is usually the variable, and it is the one you control.

011

A tool's return value is conversation history, forever

An instruction written into a tool's return string — "do not call this again" — was replayed into every subsequent turn, so the agent obeyed a months-old prohibition and silently sent nothing.

Turn-local state belongs in process state, policy belongs in the system prompt, and neither belongs in a tool's return value. Whatever a tool returns is replayed as history for the life of the conversation.

012

I was wrong three times before I asked the right question

Messages were disappearing. Three careful hypotheses, all disproven, before a single query settled it. The generalisable move is asking what the earliest thing you write down is, before your own logic can discard anything.

When input goes missing, query the earliest artifact you persist before business logic runs. Everything downstream cannot distinguish "never arrived" from "arrived and was discarded."

013

Meta stopped sending the phone number, and we dropped the message silently

WhatsApp began rolling out usernames. Senders who adopted one arrived with no phone number in the payload, our ingest discarded them with a bare continue, and nobody found out from an alert.

A guard that discards input must log what it discarded. Silence is indistinguishable from the case never occurring, and platform contracts change without asking you.

014

Catching an exception does not contain it

A best-effort helper that swallowed its own errors still broke the caller's next query, because the failed statement had already marked the transaction for rollback. It never reproduced locally, for an instructive reason.

A caught database exception still poisons the surrounding transaction. Only a savepoint contains it — try/except contains the control flow, not the connection state.

015

The 466 MB directory that reports as 296 KB

A container image was heavy because of a directory the usual size command says is tiny. Sparse files have an apparent size and an allocated size, and a build context archives the apparent one.

Measure the thing the consumer measures. A build context archives apparent size; the tool you reach for reports allocated size. They are different numbers for the same directory.

016

The guard blocked more orders than the bug it was built to stop

A safety stage added to stop the agent from confirming orders it had never placed turned out to be rejecting two-thirds of legitimate orders. Its unit tests passed because they stubbed the exact component that was broken.

A stage whose verdict nothing can corroborate is the stage that will produce your false positives, however carefully its prompt is written.
